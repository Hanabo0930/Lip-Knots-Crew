# 受信案件の取消・復旧を一往復する

受信から案件作成、行作成、合成原本の読取取込、公開、担当確定を経て、取消・原本反映・復旧・再取込までを実Firestore SDKの隔離DBで確認する。Sheetsとメール取得は合成応答のみを使い、実業務には接続しない。

復旧は元の担当者が同じ会社の有効なスタッフである場合だけ勤務枠を戻す。無効化済みまたは有効性不明のスタッフへの復旧を、案件・勤務枠・キュー・通知・監査の書込み前に拒否する。修正前はこの2条件で復旧が実行された。従来案件にも同じ有効性条件を適用する。

隔離8条件は、担当あり/なしの取消・原本同期・復旧、復旧後の遅延取消イベント、無効/有効性不明スタッフ、他案件に移った勤務枠、取消/復旧の古い確認版を扱う。復旧後に受信案件を自動募集せず、担当なしなら原本照合後の版付き手動公開が必要。appOverrideは原本の結果確認後に削除されるため、false保持とは仮定しない。

正式CIにmail-cancellation-journeyを登録し、旧来の取消・勤務枠保護および認証ガードの回帰も実行する。実worker配備、実原本変更、実通知、既存キュー再実行、停止解除、Rules/IAM/Live変更は行わない。隔離成功は実認証・端末・旧worker移行の受入完了を意味しない。
