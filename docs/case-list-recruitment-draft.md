# 案件リストの募集確認と募集メール文面

既存の `updateJobPublication` が案件公開と非公開の `caseListApprovals/{jobId}` を同じ transaction で保存する。今回の文面作成は、この承認を読み直す **既存 `generateJobExport` の `purpose: recruitment-draft` 分岐**である。別の publisher、GAS 公開処理、メール送信処理は追加しない。従来の請求・支払 CSV 分岐は維持する。

## 操作する場所

1. 原本「案件リスト」の BD「状態」が `募集中`、BE「地域」が本人の確認した地域である対象を、既存の案件リスト取込で取り込む。
2. 管理アプリ「案件一覧 → その他の操作 → 募集開始」で、現在の原本の地域・日給・単日1名・時間・未手配・解消した確認事項を確認する。地域は現在の BE と完全一致する入力だけを受理する。空の BE をアプリの入力で埋めたことにはしない。
3. 公開済みの CaseList 案件で条件を確認し直す場合は、同じ場所の「募集条件を再確認」を使う。同じ `updateJobPublication` へ戻り、別の承認系統を作らない。旧承認に地域確認がない場合も、この経路で再確認する。
4. 「案件一覧 → 募集メールを作成」で地域を1つ選び、**「募集文に掲載」チェック**で1〜20件を選ぶ。4種類の件名と任意のお知らせを選び、募集文を作成する。
5. 「再照合して件名をコピー」「再照合して本文をコピー」は、同じ選択ID・版をサーバーへ送り直す。現在の原本・募集状態・承認を全件照合できた場合だけ、その新しい文字列をコピーする。コピーに失敗した場合は完了と表示せず、確認済みの表示文字列を手動で選択できる。

「募集文に掲載」はメール文面専用の選択であり、取消チェックや月別転記選択と共用しない。文面作成とコピーは送信完了ではない。送信は本人が既存のメール環境で行う。

## サーバーの照合と公開範囲

`generateJobExport` は既存の管理者・会社・運用停止確認の後、登録済み社長アカウントを確認する。文面分岐は strict な入力型で、選択job ID・job版・Source版、地域・件名・お知らせだけを受理する。申告された公開案件JSONや承認JSONは受け取らない。

Firestore の read-only transaction で現在の案件を読み、既存 `readCaseListPublication` を通して非公開承認、原本の固定案件ID、原本・実績台帳の現在版、会社・案件の対応、既存月別との重複、月別連携能力を再照合する。Source BD が確認待ち・終了の場合は保留を維持する。本人の別案件への手配、取消、残った担当名、各種書戻し待ち、月別参照のある案件も掲載しない。

現在の BE、社長が承認した `confirmedRegion`、要求された地域は完全一致が必要。1件でも不一致・古い版・未対応があれば全体を保留し、一部だけの文面を返さない。formatter の warnings が1件でもある場合、または件数が選択数と異なる場合も同じ扱いにする。

公開する案件項目は、承認済みの実施日・クライアント・店舗・メーカー・内容・入店・実施時間・公開日給だけである。Source C の名前、Q の備考、私用メモ、給与明細、請求・粗利、Source BK の管理JSON、台帳の業務根拠、非公開承認、案件IDや原本参照は本文や返却JSONへ入れない。任意のお知らせは本人がこの画面で入力した公開文章である。

この分岐は `exportLogs` を含め Firestore 文書を書かず、キュー・公開状態・原本・通知・メールを変更しない。結果の `dispatch: disabled` は送信機能を使っていないことを表す。照合後に将来の変更まで固定する仕組みではないため、コピー操作ごとに照合し直す。

## 現在の対応範囲と保留

| 対象 | 挙動 |
| --- | --- |
| 通常の単日・1名枠、2026年11月・12月 | 既存連携能力・原本照合に通るものを対象とする |
| 基本の公開日額 | 既存社長承認の `publicPayOffer.dailyWageJPY` と交通費・通信費全額支給を使う。私的な金融値から推定しない |
| AF:AJ の遠方・緊急・店外・繁忙・検査の追加支給 | 旧メールadapterでは公開手当だったため、非zero・不明値は文面全体を保留。基本日額へ勝手に合算したり、ラベルを省略したりしない。数式は現在の有効値がzeroと確認できる場合だけ追加支給なしと扱う |
| BM「募集注意事項」 | 非空・数式・不明な型は、公開注意事項の個別承認契約が未対応のため保留。黙って削らず、Q/私用メモで代用しない |
| 研修・OJT・ラウンダー・出口調査・グレイス/グレース | 現在のクライアント・内容・Q備考に該当するものを保留 |
| 複数日・同一担当の連日・複数枠・未確認金額/数式 | 既存原本・月別連携検査で保留。対応済みと数えない |
| 旧承認の `confirmedRegion` が未記録 | 同じ「募集条件を再確認」で現在の BE と一致する地域を承認するまで文面作成を保留 |

原本 BD/BE をアプリから変更・読戻しする native publisher は、本変更には含まれない。現時点で確認待ちや地域空欄の原本を、この文面機能だけで募集中にできるとは扱わない。新しいGAS配備、原本の更新、重要な権限変更、実送信、停止解除も実施していない。

将来のGAS候補は、レビュー済みのadapterに `scripts/build-recruitment-gas.mjs --adapter reviewed.gs --output candidate.gs` で同じ core を先頭に組み込む。adapterの境界が一意でない場合は停止し、元adapterの後半をbyte単位で保持する。既存ファイルは上書きせず、新しいローカル候補だけを作る。このコマンドはGASへ配備しない。現配備済みGASは本変更では更新していない。今後GAS側だけで独立した整形アルゴリズムを育てない。

応募・直接氏名入力後の手順は引き続き、本人のクライアントへのネームアップ → 対象の月別転記選択 → 月別書込・読戻しACK → 本人の確定表示とする。募集文の選択や作成は、その転記選択を代行しない。
