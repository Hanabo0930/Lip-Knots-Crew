# 管理者作成・複製と監査の一括保存

従来の新規作成と複製は、案件/グループ/行作成依頼のcommit後に監査を別保存していました。監査保存だけが拒否されると、案件は残ったままAPIが失敗を返す状態になりました。隔離Firestoreで監査作成をALREADY_EXISTSにして、両APIでこの部分保存を再現しています。実被害を観測した記録ではありません。

監査を同じWriteBatchのcreateに含めます。成功時は案件・グループ・行作成依頼・監査が一緒に保存され、監査IDの衝突時は全体が拒否されます。既存監査は上書きしません。監査のaction/detail/requestIdなどの形式は維持します。

`test-local-admin-creation-audit.mjs` は新規/複製、行作成の有効/無効、正常/監査拒否の8条件を実SDK/隔離Firestoreで検証します。拒否時には既存文書を含む4コレクションの内容が変わらないこと、成功時には2案件・1グループ・必要なキュー・対応する監査1件があることを確認します。既存の作成〜公開15条件も回帰確認します。

受信案件作成はもともと監査を同じtransactionへ含めているため、この変更の対象ではありません。公開/編集の監査保存は別経路です。また、commit後の応答喪失や、別の作成呼出が同じ操作へ収束することを保証する変更ではありません。通常の管理者作成/複製には操作ID再送契約がまだありません。

実worker配備・実原本操作・実業務データ変更・実送受信は行いません。
