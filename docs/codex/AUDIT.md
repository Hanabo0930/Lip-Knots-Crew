# 全体監査と改善の順序

## 送信済み下書きの後片付け復旧（2026-09-05）

Storage転送がすべて完了した時点で送信済み印をメモリとlocalStorageへ記録し、選択ファイル・確認チェックを解除してDrive処理確認へ進む。IndexedDB削除だけの失敗をアップロード失敗にせず、独立した後片付け再試行を表示する。送信済み印がある間は旧下書きの復元・保存し直しを抑止し、実データの削除成功後だけ印を解除する。別会社・担当者の分離済みdraftKeyを使用。

実IndexedDBの削除abort後、新しいモジュール状態でもlocalStorageの印から復元抑止できること、古い保存の拒否、後片付け後の新規保存を検査。実アップロード後半ハンドラーを制御応答で実行し、端末失敗でもpolling継続・ファイル解除・認証変更後破棄を確認。Staffビルド・ブラウザ・UX回帰成功。

制限: IndexedDBとlocalStorageの両方が使えない場合は、同じ画面内のメモリで復元を抑止するが、ブラウザ再起動後まで保証できない。この場合は画面に提出履歴を先に確認するよう明示する。サーバー側の一意性保証・実回線転送の検証を追加したという意味ではない。後片付けを完了するまで、その提出先の新しい下書き保存も拒否し、選択中ファイルは画面に残す。
