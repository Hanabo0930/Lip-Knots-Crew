# 経費の完了通知と現在状態の整合性

`updateExpenseReviewFromQueue`が古いイベント本文と検索時点の確認記録だけを使用していたため、確認の差替後の上書き、削除済案件の再作成、所属/担当変更後の金額反映、遅れて届いたblockedイベントによる完了の巻戻しを合成データで再現した。

最新のキュー・確認記録・案件を同じtransactionで読み、会社/案件/担当/現在queueIdと確認状態を照合する。下書きへの差替、削除、不一致、最新キューが処理中の状態では書き込まない。最新の確定状態だけを確認記録と案件へ原子的に反映し、他の経費付随フィールドは維持する。原本への書込方法や費用列、金額計算は変更しない。

実モジュールをTypeScriptから変換し、Firestore境界を合成データに差し替えた19ケースを`node scripts/test-expense-completion-integrity.mjs`で実行する。初期15ケース中11件の失敗を確認後に修正し、検索中の削除/担当変更と付随項目保持も追加した。ネットワーク・Sheets・実DBへ接続しない。SDKのtransaction再試行や実配信の試験ではない。

この修正はキュー処理結果の反映経路だけを対象とする。saveExpenseReviewDraft/completeExpenseReviewの保存競合、実表への書込、担当変更前に完了した実表の修復は別。今回のFunctionは既存配備許可外で、Hosting成功を稼働反映済みと扱わない。
