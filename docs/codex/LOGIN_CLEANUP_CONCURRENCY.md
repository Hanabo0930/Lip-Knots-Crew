# 期限切れログイン情報の清掃と並行発行

清掃の検索後に新しいログインコードが発行されると、古い検索結果を使ったbatch更新が新しいコードまで消していた。対象文書が別の清掃で削除された場合はbatch全体が失敗する問題もあった。

清掃開始時の期限判定時刻を固定し、検索で選んだ最大500件（各コレクション250件）をトランザクションで読み直す。文書が存在し、現在の期限が判定時刻より前の場合だけトークン削除/コード項目除去を行う。期限内・期限項目なし・削除済み文書は保持する。レート制限の回数や最終要求時刻を消さない。検索後だけでなく、読み直し後の競合もFirestoreトランザクションが検出する。

隔離ランナーのlogin-cleanup suiteは実Firestore SDKとローカルエミュレーターを使う。検索結果取得直後に別の書込みを挿入し、再発行・期限更新・文書削除の競合を再現する。通常期限切れ、有効期限内、重複清掃、期限項目除去、250件上限も確認する。実認証情報を渡さず外部ネットワークを禁止し、実送信・実業務データ更新は行わない。

この修正の統合はcleanupExpiredLoginTokensの配備や定期実行開始を意味しない。実配備は既存許可範囲外であり、別の具体的移行条件が必要。
