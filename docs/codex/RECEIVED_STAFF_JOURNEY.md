# 受信案件の応募・提出・経費の隔離連結試験

`test-local-received-staff-journey.mjs` は、受信解析→案件作成→行追加→原本読取→版付き公開を実コードで通した案件を使い、応募後の業務を9条件で確認します。実Firestore SDKと使い捨てのローカルEmulatorを使い、Sheets/Storage/Drive/Gmailは合成応答に限定します。呼出の認証情報は合成であり、実ログイン、トークン検証、実端末、Security Rulesを合格とする試験ではありません。

| 条件 | 確認内容 |
|---|---|
| 応募・管理確認 | 同じ応募の再送は収束。古い版の管理確認を拒否。並行確認の監査は1件。担当原本未反映時の同期は拒否 |
| 2人同時応募 | 担当1人・勤務枠1件・書戻し1件・通知依頼2件に収束 |
| 応募の版/会社境界 | 確認版なし・古い版・別会社からの応募で案件やキューを変えない |
| 担当書戻し | 実workerの要求を合成原本へ適用し、再読込で担当と管理確認を保持。再配信で書込を増やさない |
| 事前連絡 | 古い版を拒否し、体温/到着時刻の書戻し・再読込・同期完了を確認 |
| 提出・差替 | 古い版を拒否し、同一操作の並行提出と転送再送が収束。元ファイルを残し、差替転送後のみ依頼を完了 |
| 経費：DB確定先行 | 下書き前の確認版は失効。5金額のみ書戻し、DB確定後の読取で金額保持 |
| 経費：原本読取先行 | 書戻し後に原本を先に取り込んでも、現在の経費を正しく確定。完了再配信は再適用しない |
| 経費：受信内容変更 | 実受信処理で変更を検出すると、待機中の経費書戻しを停止し、変更前のDB金額を保持 |

合成Sheetsは実workerの行追加/セル更新要求を表に適用し、同じ表を実読取同期へ渡します。経費では変更対象5列以外の値が変わらないことも確認します。通知は依頼文書までの検査で、実送信や通知consumerの配備は含みません。

ローカルの先行6条件を正式試験へ整理し、経費3条件を追加しました。この試験追加で新たなアプリ不具合を再現したわけではなく、業務実装は変更していません。専用の3分CIステップに登録し、既存の隔離試験ステップの時間枠を広げません。

```sh
npm --prefix functions run build
node scripts/run-local-firestore-acceptance.mjs --suite received-staff-journey --java /path/to/java --jar /path/to/cloud-firestore-emulator.jar --evidence /path/to/new-evidence
```

実worker配備、実原本操作、実送受信、実業務API、旧IDの移行、既存キュー再実行、停止解除は含みません。実移行の新規到着制御・旧実行終了・対象worker範囲と、実認証/端末を伴う受入は別の残件です。
