# 行作成workerの停止条件

`processSheetRowCreation`と`retrySheetRowCreation`は、`LKC_SHEET_WRITE_MODE=active`の完全一致がある場合だけ従来処理へ進む。未設定・paused・空値・未知値では入口で終了し、DB照会、依頼状態の変更、再試行の予約変更、原本の読書きへ進まない。既存の書戻しworkerと同じ`sheetWriteExecutionPaused`を使用する。

行作成には、`createAdminJobGroup`などが生成する`sheetRowCreateQueue`を消費する経路がある。従来はこれら2入口に停止値の検査がなく、停止設定を渡しても依頼を変更したり再試行を予約できた。

回帰試験は実際のTSとbuild済みJSの2入口を合成境界で実行する。停止側32条件でDB/原本/認証呼出しと依頼変更がないことを確認し、有効側4条件で既存の全体停止確認と再試行予約の経路を維持する。修正前は停止側32条件が失敗、有効側4条件が成功し、修正後は36条件すべて成功する。実クラウド呼出し、実原本操作は行わない。

この修正はソースの停止対応であり、配備済みの旧revisionの静止や新規イベントの到着停止を証明しない。workerの配備許可リスト、IAM、Scheduler、受付・書戻しの有効化は変更しない。既存キューを再実行せず、旧workerの移行は対象資源・静止条件・通常保護経路を別途確認して扱う。
