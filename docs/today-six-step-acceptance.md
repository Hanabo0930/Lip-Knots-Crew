# 案件リストから月別反映までの受入

2026-10-29の本人指示により、本日テストする連続工程を優先する。この文書は合格証明ではない。募集登録の保存、メール送信、応募受付、Source反映、月別ACKを別の実結果として確認する。

| 工程 | 操作と合格条件 |
| --- | --- |
| 案件リスト→募集メール作成 | 既存の募集メール作成機能で対象を選ぶ。未手配・非取消の固定案件ID、日付、店舗、メーカー、業務、入店/勤務時間、公開日給・交通費・通信費を確認。通常と東北を混ぜず、非公開の請求・支払明細を入れない。 |
| 募集をかける | 既存の送信画面で本人が対象・本文・送信先を確認する。同じ操作を二重送信せず、実送信の結果を確認する。Crewの募集原本確認登録はdispatch=disabledであり、送信成功の証拠にはしない。 |
| 応募が来る | メール応募とアプリ応募のどちらでも、案件ID・勤務日・スタッフIDを照合する。重複、他人、別会社、締切後、当日競合は保留。実応募の受信結果とデモの成功を混同しない。 |
| 名前を入れる | アプリ応募は既存Source C投影へ。本人が直接C列へ入力する場合は既存の案件リスト取込で観測する。名簿で一意に解決するスタッフだけを確認待ちにし、ここでは月別へ移さない。 |
| ネームアップ | 本人がクライアントへの連絡を完了する。名前入力・応募・取消チェックをネームアップ完了や月別選択の代わりにしない。 |
| 選択→シフト表へ反映 | 管理アプリ「概要→書戻しの確認」で、対象の「この案件を選択してシフト表へ移行」を操作する。月別への書込と読戻しACK、案件ID/スタッフID、日付、金額・数式・メモの保持を確認後に本人の確定シフトとアプリ内カレンダーへ反映。通常案件・募集の二重表示と二重操作がないことも確認する。 |

最初の対象は対応済みの通常・単日・1名・2026年11月/12月とする。研修/OJT/ラウンダー/複数日/グループ/他月/未対応金額・数式は保留する。Source A/BLは取消専用で、月別選択に兼用しない。

実業務原本は引き続き読取専用。合成・隔離検証と、本人が行う実業務テストの許可は分ける。準備・既存の成功済みコピー試験・GAS設置・旧失敗runを重複実行しない。現在の阻害と実際に合格した工程はMASTERとPRへ日時付きで記録する。

初期確認時点では、募集メールの実作成入口・実送信/実応募の接続、配備済みCaseList worker/設定と実認証、実月別ACKは未受入である。UI表示やローカル試験だけで全工程が完成したと報告しない。
